# Zeus and live lifecycle release

Scope: Jarvis is the primary Zeus entry, browser voice commands require an active paid creator subscription or an explicit operator-issued voice grant (UI plus agent-chat), `/live` redirects to `/lives`, broadcasts last up to four hours, and live archives expire 30 days after ending.

Voice grant follow-up: apply `20261105172310_voice_command_grants.sql`, then redeploy `agent-chat` with `_shared/creator-access.ts` before publishing the client. `voice_command_access()` and the server handler use the same eligibility rules. Only an operator/service can issue or revoke a grant; authenticated users can read only their own active grant. Resolve the exact confirmed account through authorized administration before inserting one row. Do not hardcode an email in client code or modify billing, roles, device trust, or keys. Grants only unlock supported voice commands; existing action confirmations and permissions remain required. To revoke, set that grant's `revoked_at=now()`. The server refuses the next voice request immediately; the UI refreshes within a minute. Roll back the client and handler first if needed; preserve the entitlement table and audit information rather than dropping it.

Deploy the server before publishing the client. This release adds one migration, `20261104215904_live_archive_lifecycle.sql`, and modifies these Cloud functions: `agent-chat`, `livekit-token`, `r2-upload`, `r2-presign`. It adds `live-maintenance`. Include the referenced `_shared` modules. Do not deploy unrelated migrations.

Cloud rejected the initial migration's Vault access with `Agent access to secrets is not allowed`. That version was not applied. The revised migration has no secret access or outbound HTTP: the `live-broadcast-deadline` SQL job ends overdue records every minute. Verify its execution, the migration history, and function versions. Never replace the platform's credential restrictions with a public or unauthenticated maintenance endpoint.

Physical media purge and forced LiveKit room closure require a separately configured operator scheduler invoking the authenticated `live-maintenance` function. No such external scheduler is provisioned by this migration. Call `{ "dry_run": true }` as an administrator first to verify the schema and LiveKit configuration without deleting data. Automatic media purge must remain reported as pending until an operator configures the supported scheduler and a disposable storage deletion has been tested. Until then, expired archives are hidden and normal host clients stop broadcasting at the deadline, but physical erasure and forced disconnect of an uncooperative client are not guaranteed.

The server freezes start/end timestamps, hides expired archives even before cleanup, closes only `live-*` LiveKit rooms (not `call-*`), then removes expired archive media and cascading chat/views in bounded batches. Media still referenced by a deliberate publication are retained. Failed lookups or unconfirmed storage deletions leave the record for retry and return 503 with counts. No message contents, tokens, or media URLs are logged.

New archive uploads use a full account UUID namespace. Legacy abbreviated paths are not ownership proof: their files are not automatically deleted, and are reported as `LIVE_ARCHIVE_PURGE_RETRY`. Inventory those separately. Physical erasure also requires checking CDN cache invalidation/retention for the public media host; deleting an origin object cannot revoke copies already downloaded by viewers.

Before activation, inventory the number of archives older than 30 days and associated files. Test storage deletion on disposable owned archives, a referenced archive, a malformed URL, and a simulated R2 error. Verify that a creator can start a live and a non-creator can still watch one; test creator/non-creator voice requests against the deployed agent-chat handler. Browser audio on iOS requires a direct gesture.

Rollback: unpublish the client to the previous served version, redeploy the previous functions, and unschedule `live-broadcast-deadline` if the database deadline must stop. Disable any separately provisioned maintenance scheduler before changing retention. Keep `archive_expires_at` and existing data; do not drop tables or restore old messages. The migration changes eligibility but does not immediately delete archive rows or files. Storage deletions are irreversible without an object backup/version. Restore the previous `live_feed_bundle` definition and remove the lifecycle guard/restrictive policy only as a reviewed database rollback; do not run a blanket database reset.

Reference: Meta's published Instagram Live announcement describes four hours and 30-day archives: https://about.fb.com/ja/news/2020/10/live_creator_bundle/ . It is not a claim that every Instagram account currently receives the same duration or that ForSure duplicates all Instagram behavior.
